工程化不是炫技，而是让团队的产出稳定、可预期。这篇文章是我在多个项目里沉淀下来的实践清单。

## 脚手架与目录结构

一个项目从零开始，最重要的事情是**约定**。推荐使用 monorepo 管理多包项目：

```text
apps/
  web/      # 主应用
  admin/    # 管理后台
packages/
  ui/       # 组件库
  utils/    # 公共工具
```

## CI/CD 流水线

每次合并到主分支，自动执行：

1. 安装依赖并做缓存
2. lint + 类型检查
3. 单元测试与构建
4. 产物上传到对象存储
5. 通知群与部署平台

> 流水线的核心不是"自动化"本身，而是**反馈速度**。构建超过 10 分钟，开发者就会开始绕开它。

## 性能监控

上线只是开始。建议接入 Web Vitals 采集，并把核心指标画成趋势图：

| 指标 | 目标 |
| ---- | ---- |
| LCP | < 2.5s |
| INP | < 200ms |
| CLS | < 0.1 |

## 小结

工程化的每一步都可以独立推进，不必一次到位。先把"合并即发布"做起来，收益立竿见影。
